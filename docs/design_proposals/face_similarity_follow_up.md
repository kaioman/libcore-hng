# 顔類似度機能の今後の調整項目

## 1. 目的

この文書は、顔類似度機能を実運用できる状態にするため、未完了の確認・調整事項と対応方法をまとめます。

現在の実装は[face_similarity.py](../../src/libcore_hng/utils/face_similarity.py)、モデル設定は[models.lock.json](../../configs/models.lock.json)です。モデル重みのSHA-256、判定閾値、品質基準が未確定の間は、実モデルを使う初期化・比較は完了しません。未確定値を推測で埋めず、以下の手順で検証してから更新してください。

## 3. YuNetランドマーク順の確認と位置合わせ修正

### 現状の懸念

`FaceDetectorYN`の検出結果に含まれる5点ランドマークを、そのままArcFace系の112×112基準点へ渡しています。検出器の点順と基準点の点順で左右の目・口角が逆なら、誤った対応で顔を変形してから特徴量を計算することになります。

### 対応方法

1. 固定するYuNetモデルとOpenCVのバージョンに対応した公式仕様を確認し、5点の順序を記録します。
2. AuraFace／ArcFaceの位置合わせ基準点が要求する点順と照合します。左右の名称だけで判断せず、画像座標上の並びも確認します。
3. 順序が異なる場合は、位置合わせに渡す直前にランドマーク配列を並べ替えます。角度判定に使う順序も明示的に扱い、誤って一方だけの順を変えないようにします。
4. 合成画像または既知のランドマークを使う単体テストで、左目・右目・鼻・口角が期待座標へ変換されることを確認します。
5. 正面・左右斜めの実画像で切り抜き・位置合わせ結果を目視確認し、評価データで比較スコアへの影響を確認します。

## 4. `models.lock.json`の未設定値を埋める

現在の[models.lock.json](../../configs/models.lock.json)には、実行時に必要な値として次が未確定です。

- AuraFaceの`recognition.sha256`
- YuNetの`detector.revision`、`detector.sha256`、`detector.license`
- `thresholds.match`と`thresholds.no_match`
- `quality.min_face_size`、`quality.min_blur_variance`、`quality.max_landmark_asymmetry`

### モデル識別情報とハッシュ

1. AuraFaceの固定リビジョンから`glintr100.onnx`を取得し、対象ファイルのSHA-256を計算します。
2. YuNetについても、配布元の固定コミットまたはリリースを選び、ファイル名・リビジョン・ライセンスを確認してモデルファイルを取得します。
3. WindowsではPowerShellの`Get-FileHash -LiteralPath <モデルファイルのパス> -Algorithm SHA256`で各ファイルのハッシュを計算します。
4. 各モデルの`revision`と`sha256`を別の値として記録し、ハッシュを`models.lock.json`に設定します。
5. 実ファイルとロック値を使った検証で、一致時は読み込み、不一致・未設定時は明示的なエラーになることを確認します。

モデルの実行時ダウンロードは行いません。`model_dir`を明示した場合はそこへ、未指定の場合は`platformdirs`が返すユーザーキャッシュ配下の`models`ディレクトリへ両モデルを配置します。

### 閾値と品質値

`null`を仮の数値に置き換えて動作確認だけを済ませないでください。現在のコードはこれらを必須数値として検証するため、`null`のままでは初期化に失敗します。

- `thresholds.match` / `thresholds.no_match`: 同一人物・別人の代表画像を含む評価データでスコア分布を計測し、誤一致と誤不一致の許容度に応じて決めます。`-1 <= no_match < match <= 1`を満たす必要があります。
- `quality.min_face_size`: 想定利用画像で顔の画素サイズと結果の関係を調べて決めます。
- `quality.min_blur_variance`: 対象画像のぼけ具合と比較品質を評価して決めます。この値は現在のLaplacian分散による指標の尺度に合わせます。
- `quality.max_landmark_asymmetry`: 正面顔と斜め顔で実装中の非対称性指標を計測し、判定保留の境界を決めます。この指標は角度そのものではありません。

評価に使う画像は、利用目的・同意・アクセス制御を確認したものに限定します。評価結果、データ条件、モデルと閾値の版を記録し、後から再現できるようにします。

## 5. 実モデルの入出力・前処理検証

1. 固定した`glintr100.onnx`のONNX入力・出力名、テンソル形状、データ型を確認します。
2. 推論コードのRGB/BGR順、画素値の正規化、112×112への位置合わせがモデルの期待仕様と一致することを確認します。
3. 既知画像で埋め込みが有限値かつ非ゼロであること、正規化後のノルムが概ね1になることを確認します。
4. 既知の同一人物ペア・別人ペアでスコアの分布を確認し、モデルカードの利用例だけを根拠に精度を想定しないようにします。
5. 推論時にモデルを自動取得するInsightFace APIは使用せず、ロックファイルで検証した個別モデルだけを使用します。

## 6. 低品質画像の扱い

現在の`max_landmark_asymmetry`は、ランドマークの左右差を使う近似指標です。実際の顔向き角度を直接推定するものではありません。

1. 正面、左右の斜め、横顔、低解像度、ぼけ、遮蔽を含む評価セットを用意します。
2. 顔サイズ、ぼけ指標、ランドマーク非対称性と比較スコアを記録します。
3. 基準外画像について、意図どおり`REVIEW`、`score=None`、理由付きで返ることを確認します。
4. 指標が角度判定に十分でない場合は、`max_landmark_asymmetry`を角度の代替と見なさず、別の姿勢推定方式を評価します。

## 7. テストの追加

`tests/utils/test_face_similarity.py`を追加し、実モデルのダウンロードを必要としないモック中心のテストを作成します。

- 正しいリビジョン・SHA-256でモデルを読み込み、不一致・欠落・不正形式で失敗する
- モデル保存先の明示指定と、`model_dir`省略時の既定キャッシュパスを使う
- 検出なしなら`DETECTION_FAILED`・`score=None`を返す
- 複数顔なら面積最大の顔を選ぶ
- 顔サイズ・ぼけ・ランドマーク非対称性が基準外なら`REVIEW`・`score=None`を返す
- `match`境界以上、`no_match`境界以下、その間の各判定を確認する
- 検出器・認識器の各リビジョンが結果に含まれる
- ランドマークの順序と位置合わせ結果が既知の対応になる

実モデルを使うテストは単体テストから分け、モデルファイルが用意された環境で明示的に実行します。

## 8. 依存関係・対象環境

`face-similarity`オプション依存を、Windows/Linuxの対象Pythonバージョンでインストールして確認します。特にOpenCV、ONNX Runtime、NumPyのwheel互換性と、既存の`face`オプション（MediaPipe、NumPy）との同時利用を確認します。

CPU版を初期基準にして、依存の解決、モジュールimport、単体テスト、固定モデルでの推論を実行します。GPU対応はCPU要件を満たさない場合に別途検討します。
