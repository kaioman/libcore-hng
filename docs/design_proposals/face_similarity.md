# 顔類似度比較機能の設計案

## 1. 文書の位置づけ

この文書は、2枚の画像に写る顔の類似度を比較する機能の設計案です。方針として合意した内容と、モデル評価後に確定する項目を分けて記載します。

### 合意済みの方針

- InsightFaceとONNX Runtimeを第一候補として評価し、テスト済みの対応モデル一覧から選べるようにします。
- 既定モデルとモデル保存先を用意し、利用側からモデル名・保存先を上書き可能にします。
- モデルファイルは自動ダウンロードせず、指定先にない場合は取得方法を示してエラーにします。
- 採用する学習済みモデルは、商用利用と再配布が許可されるライセンスであることを条件とします。
- CPUを基準対応とし、GPUは別途検証したオプションとして扱います。
- 類似度は`MATCH`、`REVIEW`、`NO_MATCH`の3段階で返し、顔検出失敗は別状態として扱います。
- 低品質画像は判定保留とし、スコアを`None`にして品質上の理由を返します。
- 既定モデル名、閾値、品質基準の数値は、ライセンス確認と評価後に決定します。

## 2. 目的と範囲

2枚の画像からそれぞれ顔を検出し、顔認識モデルで特徴量を抽出して類似度を計算します。結果は類似度スコアと判定区分として返します。

既存の[`ImageFile.crop_face`](../../src/libcore_hng/utils/imageops.py)は顔の検出・切り抜き機能であり、顔同士の類似度を計算するものではありません。比較機能は画像操作クラスに混在させず、独立した比較クラス／ユーティリティとして設計します。

対象は1回の比較につき画像2枚です。各画像に複数の顔がある場合は、既存方針に合わせて面積が最大の顔を対象にします。

## 3. モデルの選択と配置

- 推奨モデルを既定値として用意し、利用側からモデル名を上書きできるようにします。
- 初期段階では、ライブラリが対応・テストしたモデル名だけを選択可能にします。
- 既定モデル名は候補モデルのライセンスと性能を評価してから確定します。
- モデル保存先も利用側から指定可能とし、省略時は`platformdirs`を使ってOSごとのユーザーキャッシュ領域を使用します。
- モデルが指定先に存在しない場合は自動ダウンロードせず、取得方法が分かる例外を送出します。
- モデルファイルはサイズやライセンス上の理由からリポジトリにコミットしません。コンテナ等では永続化されたキャッシュ領域、またはデプロイ時にモデルを配置する方法を想定します。
- 使用モデル名とバージョンを比較結果またはログに残せるようにし、結果の再現・調査を可能にします。顔画像や特徴ベクトル自体はログに出力しません。
- 採用する学習済みモデルは、商用利用と再配布の両方が許可されることを確認します。モデルをリポジトリや配布物へ同梱することを意味するものではありません。

InsightFaceとONNX Runtimeを第一候補として検証します。候補のモデル重みが上記ライセンス要件を満たさない場合は、その重みを採用せず、別の適合モデルを評価します。

APIの概念案は、比較サービスの生成時にモデル設定を行い、比較メソッドに2枚の画像を渡す形です。

- モデル名：省略時は既定モデル
- モデル保存先：省略時は既定キャッシュ先
- モデルごとの判定閾値：モデル設定と一緒に解決
- 比較入力：画像2枚
- 比較結果：スコア、判定区分、使用モデル情報、必要に応じて失敗理由
- 閾値：評価済みのモデル別既定値を使用し、利用側から上書き可能

## 4. 比較処理

1. 2枚の画像それぞれで顔を検出します。
2. 顔が複数ある場合は、面積が最大の顔を選択します。
3. 顔の位置合わせを行います。
4. 顔認識モデルで特徴ベクトルを生成します。
5. 2つの特徴ベクトルからモデルで定めた類似度スコアを計算します。
6. モデルに対応付けられた閾値に基づいて判定区分を返します。

顔検出・位置合わせ・特徴抽出は、同じモデル／モデルパックが提供する一貫した処理を優先します。切り抜きだけを行う既存処理では、顔の向きや目鼻の位置を揃える位置合わせを代替できません。

## 5. 結果と判定区分

類似度の3段階は次のとおりです。

| 区分 | 意味 | 判定例 |
| --- | --- | --- |
| `MATCH` | 一致の可能性が高い | スコアが一致閾値以上 |
| `REVIEW` | 判定保留・追加確認が必要 | 2つの閾値の間、または画像品質不足 |
| `NO_MATCH` | 一致の可能性が低い | スコアが不一致閾値以下 |

顔を検出できなかった場合は3段階判定とは別の状態`DETECTION_FAILED`を返し、スコアは`None`とします。どちらの画像で失敗したかを示す情報も返せるようにします。

顔は検出できたものの画質・顔サイズ・角度などが比較に不十分な場合は、`REVIEW`、`score=None`とし、品質上の理由を返します。具体的な品質基準はモデル評価後に決定します。

類似度比較と無関係なエラー（画像ファイルの破損、モデルの不在・ロード失敗、未対応モデルなど）は、検出失敗の結果に置き換えず、例外として呼び出し側に伝えます。

スコアはモデル固有の尺度であり、本人である確率を意味しません。スコアの定義・範囲は選定モデルに合わせて文書化し、モデルごとに一致閾値と不一致閾値を設定します。異なるモデルに同一の閾値を流用しません。

## 6. 表情差と画像品質への対応

顔認識モデルは表情差にある程度頑健な特徴量を生成することを期待しますが、表情が異なっても結果の信頼性を保証するものではありません。顔の向き、照明、解像度、遮蔽、ぼけもスコアに影響します。

信頼性を高める設計として、以下を行います。

- 表情差を含む人物照合用途で評価された顔認識モデルを選定する
- 顔の位置合わせを行い、同一の前処理・モデルで両画像を処理する
- 顔の大きさ、ぼけ、角度などの品質を確認する
- 比較に不適切な画像は無理に一致／不一致へ分類せず、`REVIEW`として扱う
- 想定利用環境に近い表情・画質・撮影条件を含む評価データで、モデルと閾値を検証する

単一の画像ペアから確実な本人判定を保証することはできません。用途に必要な誤判定率を定めたうえで、実データによる評価を行います。

## 7. 依存パッケージと実行環境

顔特徴量の抽出には顔認識モデルが、モデル推論には推論ランタイムが必要です。候補としてInsightFaceとONNX Runtimeを評価します。NumPyは特徴ベクトルの扱いに使用するため、直接利用する実装では依存として明示します。

- CPU実行：`onnxruntime`を基本候補とし、導入しやすい既定構成にします。
- GPU実行：CPU実行が要件を満たさない場合に、環境に適合する`onnxruntime-gpu`を別途検証します。GPUドライバーやCUDA等の互換性を確認します。
- CPU版とGPU版は別の実行環境の選択肢として扱い、依存の競合を避けるため同一環境への重複導入を前提にしません。
- 既存の`face`オプション依存（MediaPipeによる顔切り抜き）とは別に、類似度機能用のオプション依存グループを設ける案です。実際に必要となるパッケージ・バージョンは対象OSとPythonでインストール検証後に固定します。
- モデルのロード／推論器は比較ごとに作り直さず、初期化時に一度ロードして再利用します。

初期対象OSはWindowsとLinuxです。対応Pythonバージョンは、選定したモデル・依存パッケージとの互換性を確認してから固定します。CPU版を基準構成とし、実際の処理時間を対象環境で測定します。

## 8. ライセンスとデータ取扱い

ソフトウェアパッケージのライセンスと、学習済みモデル／重みの利用条件は個別に確認します。既定モデルとして採用する重みは、商用利用と再配布の両方が許可されることを確認します。条件を満たさない重みは採用しません。

顔画像と顔特徴ベクトルは個人情報性の高いデータとして扱い、不要な保存やログ出力を避けます。利用者側でも、取得目的・同意・保存期間などの適切な取扱いを検討する必要があります。

## 9. テスト・評価方針

- WindowsとLinuxで、顔なし、複数顔、顔検出失敗、モデル不在、未対応モデルを確認する。
- 最大面積の顔を選ぶことを確認する。
- 3段階の閾値境界と、モデルごとの閾値設定を確認する。
- 低品質画像が判定保留になることを確認する。
- 表情・向き・照明・解像度の異なる評価画像で、誤一致・誤不一致の傾向を測定する。
- 単体テストではモデル推論をモックし、実モデルを使う評価は明示的な統合テストとして分離する。
- 使用モデル、モデルバージョン、実行環境を記録し、評価を再現可能にする。

## 10. モデル評価後に確定する項目

1. 既定モデル名とテスト済みモデル一覧（商用利用・再配布ライセンス、性能、Windows/Linux対応の確認を含む）
2. モデルごとのスコア尺度と、一致・不一致の数値閾値（代表データによる調整）
3. 画質、顔サイズ、角度などの品質判定基準（代表データによる評価）
4. Windows/Linuxで対応する具体的なPythonバージョン
5. GPU版を追加する場合の対応GPU、ドライバー、CUDA等の組み合わせ
