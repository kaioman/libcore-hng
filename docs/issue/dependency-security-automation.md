# 依存関係のセキュリティ管理と更新自動化

## タイトル

依存関係の脆弱性検知・更新とリリース検証を自動化する

## 背景

現状、`pyproject.toml` と `requirements.txt` では依存パッケージのバージョン範囲が定義されていません。また、実装では `requests` を直接 import していますが、これらの依存一覧には明示されていません。

リリース workflow はタグ push を契機にパッケージをビルド・公開しますが、依存関係の脆弱性検査やテストを実行する工程がありません。このため、依存の更新漏れ、環境ごとの解決結果の差異、または脆弱な依存を含むリリースを検知しにくい状態です。

一方、このリポジトリはライブラリであるため、開発環境の再現性を確保するロックと、利用者側の依存解決を不必要に制約しない公開依存の方針を分ける必要があります。ロックファイルを導入する場合も、更新 PR と自動検証を継続し、古い依存を固定したままにしない運用が必要です。

## 対象

- `pyproject.toml` および `requirements.txt` の依存関係定義
- 依存関係の更新・脆弱性検知の自動化
- CI およびリリース workflow のテスト・ビルド・脆弱性検査

## 対応内容

- 直接 import しているパッケージを依存一覧に明示する。
- 公開ライブラリの依存バージョン範囲と、開発・テスト環境のロック方針を分けて定義する。
- 依存更新 PR を定期作成し、脆弱性修正は定期更新を待たずに通知・提案する仕組みを導入する。
- PR の CI でテスト、パッケージビルド、依存脆弱性スキャンを実行する。
- リリース工程で必要な検証が成功しない場合は、公開を停止する。
- 更新ポリシーを定義する。少なくとも、低リスク更新の自動マージ条件と、メジャー更新・互換性に影響する更新の人手レビュー条件を明記する。

## 受け入れ条件

- `pyproject.toml` からのクリーンインストールで、パッケージの直接依存が不足なく導入される。
- 開発・テスト環境を再現できる依存管理方法が定義され、更新時にロックまたは依存解決結果が更新される。
- 定期的な依存更新 PR と脆弱性検知が設定され、更新を放置しない運用が可能である。
- 依存更新 PR でテスト、ビルド、脆弱性スキャンが自動実行され、失敗時はマージ・リリースできない。
- 公開依存の互換性方針と、依存更新のレビュー／自動マージ方針が文書化されている。

## 補足

- ロックファイルは更新を止める目的ではなく、検証対象となる依存解決結果を再現するために使う。更新 PR の自動作成、CI 検証、脆弱性アラートと組み合わせる。
- 脆弱性スキャンの結果は、人が実際の利用状況・影響範囲・緊急度を確認し、必要な更新やリリースを判断する。
- 重大な脆弱性が確認された場合は、通常の定期更新を待たない緊急対応手順を設ける。
